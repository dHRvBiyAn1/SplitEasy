# Saved friends and accessible group balances

G02.1 adds a private saved directory, independent of whether people owe anything today. This is the first serial G02 slice; non-group expense CRUD and personal debt/payment views follow after integration.

Authenticated clients send `X-Participant-Version: 1` and `X-Ledger-Version: 2`. Save with `POST /api/friends {groupId,participantId}` from a current group's active registered financial roster. A claimed alias resolves to its account's primary participant. Unclaimed guests need verified claim first. There is no account lookup by email/name, automatic claim, reciprocal relationship, notification or new membership.

`GET /api/friends` returns all your saved rows, even when settled or no group data is currently accessible. `GET /api/friends/{friendId}` adds `sharedGroups`, with current selected-mode balances and source group links. The stable friend ID is the registered account's primary participant UUID, always scoped to the requesting account. Unknown/other-owner detail is404. `DELETE` removes only your bookmark and is idempotent204, with no effect on money, claims, history or either person's membership.

Responses carry only the display label saved at creation, without email/phone or live profile lookup. Saving again preserves the original saved label/date. If another request removes an existing bookmark during save, the response is409 with reload/review guidance rather than a success for a missing row. Detail access derives strictly from current requester group memberships and the target's financial presence/owned original aliases, not from friendship. Former memberships and deleted groups expose no group detail on the next read. Snapshot reads may complete using a coherent authorized pre-removal snapshot when membership changes concurrently.

`balances:[{currency,netMinor}]` uses explicit integer minor units; positive means the friend owes you. Totals cover current accessible groups only. USD+100 and USD-100 in separate groups yields USD0 but `hasOpenObligations:true`: even overall, with group obligations still open. Different currencies never combine. `sharedGroupCount:0`, `balances:[]` means no shared group data currently available, not globally settled. HTTP errors are unavailable reads, not zero balances. Existing group history and settlement are reached through authorized source links; this slice creates no friend-only payments or personal expense history.

V18 is additive and initially empty: private directed account references and a saved label/time. Existing monetary identities/amounts/splits/history/receipts remain unchanged. Retain this table during application rollback so saved friends survive; G01's compatible-forward-fix requirement continues for guest data. No production promotion or SMTP configuration is part of this change.
