Group and expense POST accept optional UUID operationId. V12 stores a transactional claim keyed by authenticated actor, kind, scope and operation ID, submitted intent and original response. PostgreSQL ON CONFLICT waits for competing claims; a fresh READ COMMITTED lookup returns the original response or409 for changed intent. Expense replay reauthorizes current membership first. Group replay also requires current membership in its original group. Omitted IDs retain legacy additive writes. Original responses survive subsequent edits/deletion; deleted group replay cannot recreate resources.

Expense detail includes version. PUT accepts expectedVersion and DELETE accepts expectedVersion query parameter. Compare after current group lock/reauthorization and before any changes. Mismatch409 retains winner and draft. No disabled/infinite setting. Hibernate versioning protects stale concurrent persistence too. Group PATCH dirty-column semantics stay unchanged.

A small account-owned pending-intent store uses sessionStorage: reload durable, tab-isolated, no offline dispatch or automatic retry. Save persists the ID and submitted intent before HTTP; identical explicit retries reuse it; changed intent is blocked until an explicit abandon/new-intent acknowledgement warns that the prior request may already have succeeded; it then gets a new ID. Account/session reset clears this tab's pending records and old callbacks cannot remove newer intents. Modals restore uncertain drafts and require deliberate save. Payment retains original existing replay semantics and gains reload durability. Storage failure blocks mutation with actionable feedback rather than pretending the identity is durable.
