## Decisions for review before implementation

- Historical expenses, participant shares, adjustments and payments are USD, as confirmed by the owner. User preferred currency never determines historical denomination.
- Supported catalogue: USD/EUR/GBP/INR exponent2, JPY exponent0, KWD exponent3. No FX conversion or rate provider. Every new transaction stores its explicit catalogue code.
- V15 is C01's only migration allocation; A03 V14 must integrate before V15 (the same release may contain both). Retain existing amount_cents/share_cents database columns as integer minor-unit storage to avoid a dual-writer synchronization scheme; add explicit non-null currency to expenses/payments, default USD for pre-cutover writers. Participants inherit the expense denomination. Add catalogue constraints and extend the profile currency constraint. Existing values remain numerically unchanged.
- Expense currency is immutable after creation: PUT changing denomination is rejected; the edit selector is read-only with an explanation. Currency correction/conversion requires future reviewed P03 behavior.
- New financial JSON has `currency`, `amountMinor`, `shareMinor`, `netMinor`, `viewerDeltaMinor` and corresponding named minor-unit totals. Legacy cents properties remain available only for USD values; non-USD aliases are null. No object exposes a numeric aggregate of unlike currencies. Legacy scalar headline/group totals are null when mixed; currency rows are authoritative (never a silent USD partial). Dashboard/headline and group spending totals become currency-keyed rows; People/canonical obligations/settlement rows are partitioned by currency.
- Retain USD-only `amountCents` request compatibility. New writes provide currency+amountMinor. Ambiguous/conflicting fields, missing currency with amountMinor, unsupported codes, fractional/out-of-range integers and non-USD amountCents fail400. Transaction maximum remains 1e12 minor units; all split values remain integers. Percentage basis points and weight units retain their current meaning; UNEQUAL and ADJUSTMENTS use transaction minor units. Conservation and deterministic remainder stay unchanged.
- New UI declares `X-Ledger-Version: 2` on financial requests. Legacy clients may continue USD-only operations. Requests without this contract receive409 upgrade guidance before exposing non-USD financial reads or modifying non-USD expenses. Membership leave/removal still enforces the full ledger independently of client version. This keeps old cached clients from reading non-USD numbers as dollars.
- Deployment is an all-backend cutover: stop/drain every old backend instance and financial writer before enabling non-USD creation. Old binaries' aggregate queries cannot safely read mixed denominations. No rolling mix or rollback to an old binary after non-USD persists; forward fix is the default. Retain V15 on rollback; restoring a pre-cutover backup requires reviewed reconciliation of all later financial writes. The deployment runbook must state this as a gate, not claim database defaults make mixed old servers safe.
- E02 stored create responses are immutable receipts, including old JSON snapshots. Replay reads hydrate old USD snapshots into the additive contract without updating stored JSON. Compare normalized old USD intents using their original semantic fields, so new optional denomination fields do not turn legitimate old retries into409. New receipts include denomination; same operation with different currency conflicts. Payment replay likewise compares currency+amount. Account-owned browser retry drafts without currency are USD; a preference change never changes a restored draft.
- Slice4 compatibility retirement is deferred until deployed-client verification. No production deployment, external setup or mail delivery belongs to this work.

## Serial execution and completion criteria

1. **Catalogue/additive storage (commit1).** One authenticated HTTP/PostgreSQL test first demonstrates an explicit USD denomination in an expense response. Implement catalogue/V15/additive entity/response fields preserving all old USD behavior. Finish when focused test passes and old fixture integers are unchanged.
2. **Partitioned ledger (commit2).** Add one HTTP behavioral test at a time: USD+JPY remain separate; opposing equal numbers do not cancel or permit departure; settle one leaves the other; simplified/raw modes conserve each currency; dashboard/People/group spending partition. For each, capture red, implement minimally, capture green before adding the next. Finish when all queries/projections/guards and payment replay carry currency and no cross-currency sum exists.
3. **Explicit contract/forms/formatting (commit3).** Sequential HTTP/rendered Angular tests cover KWD3/JPY0, split conservation, invalid precision/bounds, new/old retry receipts and drafts, preference changes, all formatted screens and settle prefill. Implement decimal-string parser with integer/BigInt arithmetic and use native Intl formatting. Finish with all financial display paths audited, OpenAPI validation, full backend/frontend/format/build checks and clean commits.
4. **Compatibility retirement (future release).** Retain fields now. Remove only after concrete deployed-client verification and a separately reviewed rollout.
