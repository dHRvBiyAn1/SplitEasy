## Scope and meaning

A saved friend is a private, directed bookmark to an existing registered account, explicitly chosen from a current group's active canonical financial roster. It grants neither reciprocal friendship, membership, financial ownership nor new access. Settling every debt never deletes it. This first PR deliberately implements the roadmap's directory/detail slice; personal expense CRUD and personal debt/payment are later serial PRs after integration. Unclaimed guests remain group participants and require verified claim before saving as friends; never discover or claim by name/email lookup.

## Persistence and access

V18 adds friends(owner_id,friend_account_id,display_name_snapshot,created_at), composite primary key(owner_id,friend_account_id), CHECK owner<>friend, account FKs; indexes cover every FK and owner/sort read. It adds no rows to existing installations and changes no money, historical JSON, receipts, participants, links or memberships. Display name is the authorized name saved at creation, never a global live-account/contact lookup. No email/phone appears in friend responses. Existing account/profile/financial routes stay unchanged.

Create locks and reauthorizes source group with GroupWriteGuard under READ_COMMITTED, requires participant capability, resolves requested original participant strictly within current active roster, then canonical account; reject unclaimed guest/self (including owned aliases), guessed/foreign/inactive participant with400 and helpful sanitized guidance. Insert ON CONFLICT DO NOTHING makes repeated saves of aliases/primary the same relationship. Deleting a saved friend affects only the owner's bookmark, never money/membership/the other account's directory. DELETE is idempotent204 for absent rows; read detail missing/other-owner404. A03 request auth remains mandatory.

Read list/detail under REPEATABLE_READ, first restrict directory to owner, then derive shared scopes only from current requester memberships and target canonical financial presence in that group (including retained original aliases/history). Ownership or a saved friend alone never permits group history. Use existing PairwiseBalanceService selected-mode canonical projection once per accessible group; no new netting/split algorithm, no synthetic settlement. Include actual group ledger currencies as explicit zero rows where currently settled. Checked integer addition for cross-group totals; currencies never combine.

Aggregate hasOpenObligations from per-group rows rather than total alone: USD+100 in one group and USD-100 in another is even overall with two open group obligations. List/detail totals cover accessible current-group scope only. sharedGroupCount=0 and balances=[] means no current shared group data, never proof of a settled lifetime balance. A read failure is an error, never an empty/zero fallback. Group deletion/access loss removes that group's detail immediately on the next authorized read but leaves friend bookmark and saved label. All read results are one coherent snapshot; concurrent membership removal may observe authorized pre-removal snapshot, subsequent reads cannot expose the group.

## Wire contract

All routes under /api, authenticated; X-Participant-Version:1 required for new friends routes, after owner authorization where applicable; apply existing LedgerContract.requireCurrency to returned non-USD denominations (X-Ledger-Version:2). Angular sends both capabilities.

- GET /friends -> FriendSummary[]
- POST /friends {groupId:UUID,participantId:UUID} ->200 FriendSummary (idempotent save)
- GET /friends/{friendId} -> FriendDetail (owner-only404 if unknown)
- DELETE /friends/{friendId} ->204 (owner-only idempotent)

FriendBalance={currency:USD|EUR|GBP|INR|JPY|KWD,netMinor:integer}; positive=friend owes viewer.
FriendSummary={id:canonical account/primary participant UUID,displayName:saved authorized label,createdAt:ISO instant,sharedGroupCount:integer,hasOpenObligations:boolean,balances:FriendBalance[]}.
FriendDetail extends FriendSummary with sharedGroups:[{id,name,simplifyDebts,balances:FriendBalance[]}]. Detail links to authorized existing group workflows/history; do not present a complete friend transaction feed, personal expense form or friend-only settle button in this PR.
