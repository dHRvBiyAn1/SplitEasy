# P04 + P05 — spending analytics and saved split rules (V32)

Branch `feat/alignment-p04-p05-analytics-split-rules`, PR to `dev`. Design: [Wave 10 plan](../../superpowers/plans/2026-11-25-alignment-wave10.md).

## What shipped

- **P04** `GET /api/analytics?from&to&groupId&groupBy=category|month|person` (backend `analytics/*`). One SQL read over the same active entries as the H05 CSV: non-deleted expenses on `spent_on`, refunds on their own `refunded_on` (negative, keyed to the refunded expense's category/payer), "mine" through the viewer's participant links, paid from contributions. Rows are per currency and never summed across currencies. `groupId` → `requireMember` first (403); a personal-ledger `groupId` → 404. Angular `/analytics` route: filters, one section per currency, CSS bars (`aria-hidden`) plus a table with the same numbers; negative values use a distinct fill and keep their sign in the table.
- **P05** V32 `split_rules`, `GET/POST /api/groups/{groupId}/split-rules`, `PUT/DELETE .../{ruleId}` (`splitrule/*`). EQUAL/PERCENTAGE/WEIGHTS only (EXACT/ADJUSTMENTS 400); private to the owner (another member sees an empty list and 404 on the id); versions required on PUT/DELETE (409 stale); live names unique per owner+group ignoring case (409); archived group refuses writes (409). Expense editor: a "Saved splits" toggle (rules are fetched only when opened, so the default editor makes no extra request), an "Apply saved split" select that prefills the draft only, and "Save this split as…". A rule naming someone who is no longer an active participant shows a review message and applies nothing.

## Not done / limits

- No navigation entry to `/analytics` (the shell is not in this package's ownership); reachable by URL, optional `?groupId=`. Integrator/UI to link it.
- Personal-ledger `groupId` 404 on analytics is implemented but has no dedicated test; the split-rule routes inherit `PersonalLedgerRouteGuard` (variable bound as `groupId`), also without a dedicated test.
- Rule edit/delete exist in the API only; the editor has apply and save-as.
- Rules are not checked against current membership on save (private data; membership is checked when applying).
- hi/es/fr strings are machine-drafted (Beta).
- Drain old backends before V32 only if they must write rules; old binaries ignore the table. Rollback keeps the schema.
